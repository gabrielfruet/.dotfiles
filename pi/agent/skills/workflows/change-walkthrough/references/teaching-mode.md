# Teaching mode — only when the user is unfamiliar with the code

Default register is peer-to-peer: the user owns the change, so explain and move
on. Switch to this mode only when the user is new to the code being toured — an
inherited system, someone else's module, onboarding.

## Depth ladder

Match depth to the reader and fade guidance as they show they have it. This is
the expertise-reversal effect: step-by-step help that carries a newcomer actively
slows an expert.

| Level | When | How to narrate |
|---|---|---|
| Summary | reader knows the area | one line per stop — name the site and the effect |
| Explain | following, but new to this code | full per-stop shape, one zoomed snippet |
| Teach | learning the codebase | add the *why*, the alternative not taken, a check |

Start one level above where you think they are; drop down the moment they lag.

## Comprehension checks

Teach level only. Ask them to *produce*, not to *approve*:

- "Summarize what this stop changes, in your words."
- "Given this, predict what the next stop has to change."
- "Which existing caller does this break?"
- "Confidence 1–5 that you could make this edit yourself?"

Banned — these manufacture false yeses:

- "Does that make sense?"
- "Do you understand?"
- "Any questions?" as a checkpoint (fine as a genuine offer)

Check before, during, and after a segment — not once at the end.
